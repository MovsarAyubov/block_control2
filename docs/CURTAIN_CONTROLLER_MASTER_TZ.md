# ТЗ Для Мастера: Работа С `curtain_controller`

## 1. Назначение

Мастер должен управлять шторой через Modbus RTU, читать фактическую позицию,
передавать целевую позицию, читать диагностические регистры `curtain_controller`
и корректно обрабатывать режимы связи `REMOTE` / `AUTONOMOUS`.

Цель мастера: не дергать исполнительные выходы напрямую, а работать только через
регистры и подтверждения slave.

## 2. Текущая Реализация Через Modbus

### 2.1 Обязательные Регистры И Диагностика

| Регистр | Доступ | Формат | Назначение |
| --- | --- | --- | --- |
| `8` `CURTAIN_POS` | RO | `x10 %` | Фактическая позиция шторы `0.0..100.0%` |
| `105` `CURTAIN_POS_TARGET` | RW | `x10 %` | Целевая позиция шторы `0.0..100.0%` |
| `9` `MODE_STATE` | RO | enum | `REMOTE` / `AUTONOMOUS` состояние slave |
| `10` `MODE_REASON` | RO | enum/bits | Причина текущего режима |
| `11..12` `LAST_MASTER_SEEN_MS` | RO | `uint32` | Время последнего валидного запроса мастера |
| `13` `GOOD_CYCLE_STREAK` | RO | `uint16` | Количество успешных циклов связи подряд |
| `14` `LAST_APPLY_STATUS` | RO | enum | Последний статус применения control-блока |
| `100..101` `CTRL_VERSION` | RW | `uint32` | Версия control-блока мастера |
| `125` `APPLY_STATUS` | RO | enum | Статус применения блока `100..127` |
| `126..127` `ACTIVE_CTRL_VERSION` | RO | `uint32` | Активная примененная версия |
| `243` `CURTAIN_CTRL_MODE` | RW | enum | `0=AUTO`, `1=MANUAL`, `2=OFF` |
| `244` `CURTAIN_MANUAL_TARGET` | RW | `x10 %` | Ручная цель для режима `MANUAL` |
| `267` `CURTAIN_TARGET` | RO | `x10 %` | Итоговая цель контроллера |
| `268` `CURTAIN_BASE_TARGET` | RO | `x10 %` | Базовая цель до корректировок |
| `269` `CURTAIN_CURRENT_MA` | RO | `x10 mA` | Ток позиционера |
| `270` `CURTAIN_STATUS_BITS` | RO | bits | Общий статус шторы |
| `271` `CURTAIN_REASON_BITS` | RO | bits | Причины текущей цели |
| `272` `CURTAIN_POSITION_STATUS_BITS` | RO | bits | Статус позиционирования |
| `273` `CURTAIN_FAULT_CODE` | RO | enum | Код аварии |
| `274` `CURTAIN_FAULT_RESET_TOKEN` | RW | token | Сброс аварии новым ненулевым token |

Формат процентов: значение в регистре равно процентам, умноженным на `10`.
Примеры: `0` = `0.0%`, `500` = `50.0%`, `1000` = `100.0%`.

### 2.2 Диапазоны И Валидация

Мастер обязан ограничивать `CURTAIN_POS_TARGET` диапазоном `0..1000`.
Значение вне диапазона считается ошибкой конфигурации и не должно отправляться.

Рекомендуемая логика HMI:

- `0%` - полностью закрыто.
- `100%` - полностью открыто.
- Шаг ручного задания: `1.0%` или `5.0%`, но в Modbus писать все равно `x10`.
- Не отправлять новую цель чаще, чем раз в `1 s`, если оператор не менял задание.

## 3. Порядок Работы Мастера

### 3.1 Старт После Подключения

1. Прочитать `9..14` и убедиться, что slave отвечает.
2. Прочитать `0..8`, в том числе `8 CURTAIN_POS`.
3. Прочитать `100..127`, чтобы получить текущие активные уставки.
4. Проверить `105 CURTAIN_POS_TARGET`; если значение вне `0..1000`, заменить
   его на безопасное значение из настроек проекта.

### 3.2 Запись Целевой Позиции

Предпочтительный способ для полного control-блока:

1. Сформировать новый блок `100..109`, сохранив остальные уставки:
   - `100..101` новая `CTRL_VERSION`;
   - `103` цель форточки A;
   - `104` цель форточки B;
   - `105` цель шторы;
   - `106..109` уставки воды.
2. Записать блок через `FC16`.
3. Прочитать `125` и `126..127`.
4. Считать запись успешной, если `125 = 0` и `126..127` равны новой версии.

Допустимый упрощенный способ для пусконаладки:

1. Записать только `105` через `FC06` или `FC16`.
2. Прочитать `105` обратно и сверить значение.
3. Контролировать движение по изменению `8 CURTAIN_POS`.

Если мастер уже управляет всем control-блоком, нельзя писать только `105` из
отдельного потока, потому что это может перетереться следующей полной записью
`100..109`.

### 3.3 Runtime-Цикл

Рекомендуемый период цикла: `1 s`.

Каждый цикл мастер должен:

1. Выполнить хотя бы один валидный Modbus-запрос для heartbeat.
2. Прочитать `8 CURTAIN_POS`.
3. Прочитать `9..14`.
4. При активном управлении сравнить `8` с `105`.
5. Если позиция долго не меняется после изменения цели, вывести предупреждение
   оператору, но не пытаться включать выходы напрямую.

## 4. Поведение При Потере Связи

Любой валидный Modbus-запрос является heartbeat. Если slave не получает валидные
запросы более `30 s`, он переходит в `AUTONOMOUS`.

Требования к мастеру:

- Поддерживать опрос чаще `30 s`; рекомендуемый период `1 s`.
- После восстановления связи дождаться `3` успешных циклов подряд.
- После возврата в `REMOTE` перечитать `100..127` и только потом отправлять
  новую цель шторы.
- Не считать потерю связи командой на остановку шторы; это решает slave.

## 4.1 Аппаратные Выходы Slave

Мастер не управляет выходами напрямую, но для пусконаладки важно знать
назначение линий slave:

- `74HC595 bit14` - команда шторы `OPEN`.
- `74HC595 bit15` - команда шторы `CLOSE`.
- Позиционер шторы читается через ADS1115 `0x48`, дифференциальный вход
  `AIN2-AIN3`, токовый сигнал `4-20 mA` через шунт `109.3 Ohm`.

## 5. Требования К Интерфейсу Оператора

На экране управления шторой должны быть:

- Фактическая позиция `CURTAIN_POS`, `0.0..100.0%`.
- Целевая позиция `CURTAIN_POS_TARGET`, `0.0..100.0%`.
- Индикатор режима slave: `REMOTE` / `AUTONOMOUS`.
- Индикатор свежести связи: время с последнего успешного ответа.
- Предупреждение, если цель изменилась, а позиция не меняется дольше
  проектного таймаута.

Оператору не показывать сырое значение `x10`, только проценты.

## 6. Полный Блок `curtain_controller`

Блок `243..274` уже выделен под `curtain_controller`.

| Регистр | Доступ | Формат | Назначение |
| --- | --- | --- | --- |
| `243` `CURTAIN_CTRL_MODE` | RW | enum | `0=AUTO`, `1=MANUAL`, `2=OFF` |
| `244` `CURTAIN_MANUAL_TARGET` | RW | `x10 %` | Ручная цель для `MANUAL` |
| `245` `CURTAIN_SCHEDULE_START_HHMM` | RW | `HHMM` | Начало активного периода |
| `246` `CURTAIN_SCHEDULE_END_HHMM` | RW | `HHMM` | Конец активного периода |
| `247` `CURTAIN_OUTSIDE_TARGET` | RW | `x10 %` | Резерв для политики вне расписания |
| `248` `CURTAIN_MIN_POSITION` | RW | `x10 %` | Минимальная допустимая позиция |
| `249` `CURTAIN_MAX_POSITION` | RW | `x10 %` | Максимальная допустимая позиция |
| `250` `CURTAIN_POSITION_HYST` | RW | `x10 %` | Гистерезис позиционирования |
| `251` `CURTAIN_RADIATION_THRESHOLD` | RW | `W/m2` | Порог радиации |
| `252` `CURTAIN_RADIATION_STEP_WM2` | RW | `W/m2` | Шаг радиации |
| `253` `CURTAIN_RADIATION_STEP_PERCENT` | RW | `x10 %` | При активной радиации target = `248 + step_count * 253` |
| `254` `CURTAIN_RADIATION_HYST` | RW | `W/m2` | Гистерезис радиации |
| `255` `CURTAIN_COLD_DELTA` | RW | `x10 C` | Дельта ниже `275`; включение при `275 - 255 - 256`, отпускание при `275 - 255` |
| `256` `CURTAIN_COLD_HYST` | RW | `x10 C` | Гистерезис холодного закрытия |
| `257` `CURTAIN_COLD_TARGET` | RW | `x10 %` | Цель при холоде |
| `258` `CURTAIN_HEAT_DELTA` | RW | `x10 C` | Дельта выше `275`; включение при `275 + 258 + 259`, отпускание при `275 + 258` |
| `259` `CURTAIN_HEAT_HYST` | RW | `x10 C` | Гистерезис жары |
| `260` `CURTAIN_HEAT_TARGET` | RW | `x10 %` | Цель при жаре |
| `261` `CURTAIN_HUM_LOW_DELTA` | RW | `x10 %RH` | Дельта ниже `276`; включение при `276 - 261 - 262`, отпускание при `276 - 261` |
| `262` `CURTAIN_HUM_LOW_HYST` | RW | `x10 %RH` | Гистерезис нижнего порога |
| `263` `CURTAIN_HUM_LOW_TARGET` | RW | `x10 %` | Цель при низкой влажности |
| `264` `CURTAIN_HUM_HIGH_DELTA` | RW | `x10 %RH` | Дельта выше `276`; включение при `276 + 264 + 265`, отпускание при `276 + 264` |
| `265` `CURTAIN_HUM_HIGH_HYST` | RW | `x10 %RH` | Гистерезис верхнего порога |
| `266` `CURTAIN_HUM_HIGH_TARGET` | RW | `x10 %` | Цель при высокой влажности |
| `267` `CURTAIN_TARGET` | RO | `x10 %` | Итоговая рассчитанная цель |
| `268` `CURTAIN_BASE_TARGET` | RO | `x10 %` | Базовая цель до защитных поправок |
| `269` `CURTAIN_CURRENT_MA` | RO | `x10 mA` | Ток позиционера |
| `270` `CURTAIN_STATUS_BITS` | RO | bits | Общий статус |
| `271` `CURTAIN_REASON_BITS` | RO | bits | Причины текущей цели |
| `272` `CURTAIN_POSITION_STATUS_BITS` | RO | bits | Статус позиционирования |
| `273` `CURTAIN_FAULT_CODE` | RO | enum | Код аварии |
| `274` `CURTAIN_FAULT_RESET_TOKEN` | RW | token | Сброс аварии по новому token |

В `AUTO` базовая цель шторы равна регистру `248` (`CURTAIN_MIN_POSITION`).
Активные правила автоматики назначают свою цель (`radiation`, `257`, `260`,
`263` или `266`). Если ни одно правило не активно, итоговая цель остается `248`.
Если одновременно активно несколько правил, приоритет target такой: перегрев
(`260`) -> переохлаждение (`257`) -> высокая влажность (`266`) -> низкая
влажность (`263`) -> радиация.

`MODBUS_HREG_TOTAL_COUNT` now extends beyond the curtain block because later
blocks are used by shared greenhouse targets, CO2 control, and circulation fans.

### 6.2 Статусы `CURTAIN_STATUS_BITS`

- `bit0` управление активно, есть выход `OPEN` или `CLOSE`.
- `bit1` режим `MANUAL`.
- `bit2` режим `AUTO`.
- `bit3` режим `OFF`.
- `bit4` позиция валидна.
- `bit5` идет открытие.
- `bit6` идет закрытие.
- `bit7` цель достигнута.
- `bit8` есть авария.
- `bit9` активен выход `OPEN`.
- `bit10` активен выход `CLOSE`.

### 6.3 Причины `CURTAIN_REASON_BITS`

- `bit0` активно расписание.
- `bit1` активно правило радиации.
- `bit2` холодное закрытие.
- `bit3` открытие при жаре.
- `bit4` открытие при низкой влажности.
- `bit5` закрытие при высокой влажности.
- `bit6` ручной режим.
- `bit7` вне расписания.
- `bit8` ошибка датчика температуры.
- `bit9` ошибка датчика влажности.
- `bit10` ошибка радиации.
- `bit11` ошибка времени.

### 6.4 Коды Аварий

- `0` `NONE` - аварии нет.
- `1` `ENCODER` - позиционер/энкодер невалиден.
- `2` `NO_MOTION` - команда движения есть, но позиция не меняется.
- `3` `OUTPUT` - ошибка записи выходов.

Мастер обязан показывать fault оператору и не слать повторяющиеся команды
движения как способ "продавить" аварию. Сброс выполнять только по явному
действию оператора через новый `CURTAIN_FAULT_RESET_TOKEN`.

## 7. Источники Данных Для Автоматического Режима

Для `AUTO` мастер должен регулярно поставлять данные, которые уже используются
другими контроллерами:

- время через RTC sync `140..144` или валидное локальное RTC slave;
- погоду через `158..168`;
- радиацию через `163 WEATHER_SOLAR_RAD`;
- уставку температуры воздуха через соответствующий регистр климат-контроля;
- влажность и температуру воздуха slave читает локально из телеметрии.

Если входные данные невалидны, `curtain_controller` выставляет reason-биты
ошибок и не должен получать от мастера "ручную компенсацию" каждую секунду.

## 8. Критерии Приемки

Минимальная приемка текущей версии:

1. Мастер читает `8 CURTAIN_POS` и отображает проценты корректно.
2. Мастер пишет `105 CURTAIN_POS_TARGET` только в диапазоне `0..1000`.
3. При записи `50.0%` в регистре появляется `500`.
4. После изменения цели мастер отслеживает изменение `8`, но не управляет
   физическими выходами напрямую.
5. При отсутствии связи больше `30 s` мастер показывает потерю связи и после
   восстановления перечитывает `100..127`.

Приемка расширенной версии:

1. Мастер поддерживает режимы `AUTO`, `MANUAL`, `OFF`.
2. В `MANUAL` мастер пишет ручную цель, а в `AUTO` пишет настройки алгоритма,
   но не перезаписывает рассчитанную цель.
3. Мастер отображает `CURTAIN_STATUS_BITS`, `CURTAIN_REASON_BITS` и
   `CURTAIN_FAULT_CODE` человекочитаемо.
4. Сброс аварии доступен только отдельной операторской командой.
5. При fault-кодах `ENCODER`, `NO_MOTION`, `OUTPUT` мастер прекращает
   автоматические повторные записи цели до сброса/диагностики.
