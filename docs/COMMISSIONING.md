# Пусконаладка И Подключение К Мастеру

## 1. Назначение
Документ описывает минимально необходимые шаги для запуска slave-узла, проверки модулей и интеграции с мастером по Modbus RTU.

## 2. Аппаратные Подключения

### 2.1 RS485
- UART2 RX: GPIO25
- UART2 TX: GPIO26
- UART2 RTS (DE/RE): GPIO27
- Параметры линии: 19200, 8N1
- `slave_id`: из NVS, диапазон `1..247`

### 2.2 I2C
- SDA: GPIO21
- SCL: GPIO22
- На I2C подключены: ADS1115, DS3231

### 2.2.1 ADS1115
| ADDR pin | I2C address | Назначение |
| --- | --- | --- |
| GND | `0x48` | RH sensor |
| VDD | `0x49` | Позиционеры форточек A и B |
| SDA | `0x4A` | Резерв |
| SCL | `0x4B` | Резерв |

- ADS1115 `0x49`, `AIN0-AIN1`: позиционер форточки A
- ADS1115 `0x49`, `AIN2-AIN3`: позиционер форточки B

### 2.2.2 SPI / MAX31865
- SPI host: `SPI2_HOST`
- ESP32 `GPIO14` -> `MAX31865 SDI`
- ESP32 `GPIO12` -> `MAX31865 SDO`
- ESP32 `GPIO13` -> `MAX31865 CLK`
- ESP32 `GPIO15` -> `MAX31865 CS1`
- ESP32 `GPIO5` -> `MAX31865 CS2`
- Оба `MAX31865` используют общие линии `SDI/SDO/CLK`, различается только `CS`.

### 2.3 Исполнительные Механизмы
- Window A OPEN: GPIO32
- Window A CLOSE: GPIO33
- Window B OPEN: GPIO19
- Window B CLOSE: GPIO23
- Для каждого входа позиционера `4-20 mA` использовать шунт `109.3 Ohm`
- Рекомендуемый тип шунта: `metal film`, точность `0.1%`, мощность `0.125 W` минимум, предпочтительно `0.25 W`
- Ожидаемое падение напряжения на шунте:
  `4 mA -> 0.437 V`, `20 mA -> 2.186 V`
- В прошивке ток пересчитывается по формуле:
  `I(mA) = U(mV) / 109.3`
- 3-way valve OPEN: через `74HC595 Q2`
- 3-way valve CLOSE: через `74HC595 Q3`

### 2.3.1 74HC595
- ESP32 GPIO2 -> `SER/DS`
- ESP32 GPIO4 -> `SHCP/SRCLK`
- ESP32 GPIO18 -> `STCP/RCLK`
- `Q0` -> Relay 1
- `Q1` -> Relay 2
- `Q2` -> 3-way valve OPEN
- `Q3` -> 3-way valve CLOSE
- В текущей реализации свет и один `3-way valve` управляются через `74HC595`.
- Управление форточками вынесено на отдельные GPIO и не использует latch `74HC595`.

### 2.4 Освещение
- Relay 1: через `74HC595 Q0`
- Relay 2: через `74HC595 Q1`
- Суммарная мощность для `135 LIGHT_OUTPUT_PERCENT`:
  - `00` -> `0%`
  - `10` или `01` -> `50%`
  - `11` -> `100%`

## 3. Запуск Прошивки
1. Подайте питание и убедитесь, что RS485 и I2C физически подключены.
2. После старта инициализируются: NVS, Modbus, I2C, RTC DS3231, RH/ADS1115, RLL400, MAX31865(1/2), клапан.
3. Запускаются две задачи:
   - быстрая `200 ms`: позиционирование и управление relay света
   - медленная `5 s`: опрос датчиков, обновление телеметрии и времени

## 4. Что Обязан Делать Мастер

### 4.1 Heartbeat
- Регулярно отправлять валидные Modbus-запросы.
- При отсутствии валидных запросов более `30 s` slave перейдет в `AUTONOMOUS`.

### 4.2 Световая Конфигурация `110..122`
- `110` LIGHT_R1_ENABLE
- `111` LIGHT_R1_ON_HHMM
- `112` LIGHT_R1_OFF_HHMM
- `113` LIGHT_R1_THRESHOLD_WM2
- `114` RESERVED
- `115` LIGHT_R1_DLI_OFF_LIMIT_JCM2
- `116` LIGHT_R2_ENABLE
- `117` LIGHT_R2_ON_HHMM
- `118` LIGHT_R2_OFF_HHMM
- `119` LIGHT_R2_THRESHOLD_WM2
- `120` RESERVED
- `121` LIGHT_R2_DLI_OFF_LIMIT_JCM2
- `122` LIGHT_HYST_SEC

Правила:
- Время задается в формате `HHMM`.
- Для `ENABLE=1` интервал `ON == OFF` невалиден.
- Интервалы через полночь (`ON > OFF`) валидны.
- `LIGHT_HYST_SEC` общий для обоих relay и задается в секундах.

### 4.3 Apply Света
Предпочтительно:
1. Записать `FC16(110, 13)`.
2. Проверить `125` и `126..127`.

Допустимо:
1. Записать `110..122` несколькими запросами.
2. После последней записи выдержать не менее `250 ms`.
3. Проверить `125` и `126..127`.

Успех:
- `125 = 0`
- `126..127` изменились

Ошибка:
- `125 != 0`
- active light config/version не меняются

### 4.4 Текущее Накопленное DLI
- Записывать текущее значение `Дж/см²` в `134 LIGHT_CURRENT_DLI_JCM2`.
- Это ограничение имеет приоритет над порогами `Вт/м²`.

### 4.5 Weather Sync
- Используются регистры `158..170`.
- Порядок:
  1. Записать `FC16(158, 11)`
  2. Читать `169` и `170`, пока `169 == token`
- Мгновенная радиация для света приходит в `163 WEATHER_SOLAR_RAD`.
- Успех для мастера:
  - `170 = 2` APPLIED
  - `170 = 5` NOOP
- Ошибка:
  - `170 = 4` FAILED

### 4.6 RTC-Синхронизация
- Используются регистры `140..144`.
- Порядок:
  1. Записать `140` и `141`
  2. Записать новый ненулевой token в `142`
  3. Читать `143` и `144`, пока `143 == token`

## 5. Логика Света В Системе
1. Каждый relay управляется независимо.
2. У relay есть собственные `расписание + THRESHOLD + DLI`.
3. Вне расписания relay выключен.
4. При достижении relay-specific DLI limit relay выключается независимо от порога `Вт/м²`.
5. Если `THRESHOLD == 0` или `WEATHER_SOLAR_RAD < THRESHOLD`, relay стремится включиться.
6. Если `WEATHER_SOLAR_RAD >= THRESHOLD`, relay стремится выключиться.
7. `LIGHT_HYST_SEC` задает временное удержание перед сменой устойчивого состояния для обоих relay.
8. После перехода relay в устойчивое `ON` физическое включение откладывается на `zone_id * 10 s`.
9. В текущей реализации `zone_id = slave_id`.

## 6. Полезные Логи
- `Relay 1 schedule received ...`
- `Relay 2 schedule received ...`
- `Light cfg received ...`
- `Light cfg auto-queued from registers 110..122`
- `Light cfg auto-queued after 250 ms settle`
- `Light cfg queued for apply ...`
- `Light config applied: active_ctrl_version=...`
- `Light runtime: now=... out=... relays=...`
- `Weather sync QUEUED ...`
- `Weather sync APPLIED ...`

## 7. Проверка Пусконаладки
1. Modbus-связь стабильна, нет таймаутов на чтение/запись.
2. Телеметрия в `0..8` обновляется.
3. Валидный apply света: `125 = 0`, `126..127` увеличены.
4. Невалидный apply света: `125 != 0`, `126..127` не меняются.
5. `135` корректно показывает `0/50/100`.
6. `136` отражает состояние расписаний, задержек включения, DLI, гистерезиса и фактических выходов.
7. RTC-синхронизация дает `APPLIED`/`NOOP` для валидной команды.
8. Weather sync по `FC16(158, 11)` дает подтверждение через `169..170`.
9. При отсутствии heartbeat более `30 s` slave переходит в `AUTONOMOUS`.

## 8. Примечания
- Weather snapshot хранится только в RAM и после reboot не восстанавливается.
- Weather stale является внутренним состоянием slave и сам по себе не переводит систему в `AUTONOMOUS`.
- После reboot slave восстанавливает active light config и `ACTIVE_CTRL_VERSION` из NVS.
